Before anyone types a command

Six rules that protect our marks

#RuleWhy
1Same machines, same limits. Machine A stays Irfan's PC with the Ollama container at 4 CPUs / 8 GiB; Machine B stays Uwais's laptop. Nobody changes .env, .wslconfig or Docker Desktop resources.The brief forbids extra compute or memory, and any change between configurations voids the comparison.
2Never edit or delete a result file. A bad run is kept and redone under a new tag (e.g. run3b) with a note in results/a2/reconcile_notes.md.Every number on slides 4–7 must trace to a raw .jtl or log line. Fabricated or unreconcilable figures are an academic-integrity case.
3Don't change the rule, the predictions or the split. Cut-offs stay at 400 and 500 characters. Predictions are not revised; we explain misses instead.The commit history proves they came before the measurements. Marks go for specific predictions and the analysis of misses, not for being right.
4Pull before you start, push when you finish. git pull --rebase first, then commit only your own files, then git push. Post the hand-off message in the group chat.Phases wait on each other through GitHub. If it isn't pushed, the next person can't start.
5Machines A and B stay awake and wired during phases 1–4: sleep off, Windows Update paused, Ethernet not Wi-Fi, no games or Chrome on Machine A.A1 lost a run to a 2-minute network drop, and background load on Machine A shows up directly as latency.
6If a script says ABORT, stop. Don't work round it. Screenshot it, post it, wait for Alvin.Aborts guard the conditions the brief sets (both models loaded, digests unchanged, settings unchanged).

Waits for: phase 2 pushed

How the two machines take turns

You don't coordinate by hand. Machine A restarts Ollama, warms up, checks ollama ps, then sets /healthz to ready-<run>. Machine B waits for that, runs JMeter, then calls GET /stats, which tells Machine A the run is over. Start both scripts within a few minutes of each other and leave them alone. Either side waits indefinitely for the other.
