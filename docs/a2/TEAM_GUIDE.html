The order things must happen in

Two rules decide the whole schedule.
  • Nothing is measured before everyone signs off. The split, the escalation rule and the prediction record are already committed. Once Irfan starts the memory check they are frozen: the commit history is the evidence they came before any measurement.
  • Only one test runs on Machine A at a time. The memory check, accuracy test and speed runs all use Irfan's CPU, so one script runs them one after another: memory, accuracy, calibration, then speed. Nobody else uses Machine A that night.

Things that cost marks

Don'tWhy
Change the split, the rule, the cut-offs or the predictions after anyone starts measuringThe commit history is the evidence they came first; misses are explained, not revised
Change .env, .wslconfig, Docker Desktop resources or any Ollama settingThe client won't add CPU or RAM, and any change between configurations voids the comparison
Run a cascade test without both models listed in ollama psThat measures model loading, not the cascade. The scripts abort for this reason
Run JMeter on Irfan's PCA co-hosted load generator steals CPU, and the brief rejects those numbers
Report fewer than 3 runs per configurationThe spread across runs is part of the result
Edit or delete a .jtl or log lineEvery figure on slides 4–7 must trace to them. Redo a bad run under a new tag instead
Type a number into a slide by handThe deck builder reads every figure from the files
Run docker compose down -v or ollama pull on Machine AIt can replace the pinned model digests, and then the Assignment 1 accuracy records can't be reused
