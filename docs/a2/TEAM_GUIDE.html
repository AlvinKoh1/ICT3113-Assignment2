How to use this guide

The cascade, the escalation rule, the predictions and every script are already written and committed. What is left is measurement on our Assignment 1 machines, then analysis and the deck. This guide puts that work in order: who acts, what they type, what "done" looks like, and who they hand over to. Read Parts 1 and 2 once; then work through Part 3 in order.

PartWhat it coversWhen
1. Before you startWhat is already done, who owns what, the rules, getting the repository.Before anything
2. The order of workWho works when, which phases wait for which, the target dates.Before anything
3. The phasesEight phases, in the order they must be done. Each ends with a Done when check and says who it unlocks.12–25 Nov
4. ReferencePersonal checklists, hand-off messages, troubleshooting, file locations, glossary.Any time

Conventions

MarkMeaning
monospaceText to type or paste exactly: a command, a file or a folder.

Together, liveTwo people at the same time on two machines. The scripts hand over automatically.

Who should follow it

All five of us. Irfan and Uwais carry most of the machine work (phases 1–4); Gabriel, Alvin and Muhaimin take over from phase 5. Commands are run in a terminal: WSL on Machine A, Git Bash on Machine B, and any terminal with Python for phases 5–6. If this guide and docs/a2/RUNBOOK.md ever disagree, the runbook wins; tell Alvin.

1.3 Six rules that protect our marks

#RuleWhy
1Same machines, same limits. Machine A stays Irfan's PC with the Ollama container at 4 CPUs / 8 GiB; Machine B stays Uwais's laptop. Nobody changes .env, .wslconfig or Docker Desktop resources.The brief forbids extra compute or memory, and any change between configurations voids the comparison.
2Never edit or delete a result file. A bad run is kept and redone under a new tag, with a note in results/a2/reconcile_notes.md.Every number on slides 4–7 must trace to a raw .jtl or log line. Unreconcilable figures are an academic-integrity case.
3Don't change the rule, the predictions or the split. Cut-offs stay at 400 and 500. Predictions are not revised; misses are explained instead.The commit history proves they came first. Marks go for specific predictions and the analysis of misses.
4Pull before you start, push when you finish. git pull --rebase, commit only your own files, git push, then post the hand-off message.Phases wait on each other through GitHub. Unpushed work blocks the next person.
5Machines A and B stay awake and wired during phases 1–4: sleep off, Windows Update paused, Ethernet, no games or browsers on Machine A.A1 lost a run to a 2-minute network drop; background load on Machine A shows up as latency.
6If a script says ABORT, stop. Screenshot it, post it, wait for Alvin.Aborts guard the brief's conditions: both models loaded, digests and settings unchanged.

4.5 Glossary

TermMeaning
CascadeTwo models in one service: the small one answers short tickets, the large one answers the rest.
Cut-off (T)Ticket length in characters above which a ticket goes straight to the large model. We test 400 and 500.
EscalationA ticket whose final answer came from the large model. The fraction is read from the service log.
Tuning / test setThe two halves of the golden set. The rule was chosen on the tuning half; every reported accuracy uses the test half.
SThe middle of three single-ticket times on qwen2.5:7b. It sets the arrival rate (one ticket every 2S) and the run length (S minutes).
Open loopJMeter sends tickets on a schedule without waiting for answers, like real arrivals.
p50 / p95The median latency of a run / the latency 95 % of the way up, pooled over the three runs.
ReconcileShow that the .jtl, the JMeter log, GET /stats and the service log agree on what was sent and completed.
ResidentLoaded in memory. ollama ps lists resident models.
