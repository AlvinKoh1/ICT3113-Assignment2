1 Non-Negotiable Academic & Grading Gates

🔒 Gate 1: Git Pre-Benchmark Freeze

The Golden Test Set, Labelling Protocol, Independent Label Sheets, Agreement Statistic, and Prediction Record must be committed to GitHub before any benchmark runs appear in your logs. Commit history is verified against test timestamps.

💻 Gate 2: Two-Machine Isolation

Machine A (SUT + Docker + Ollama on CPU) and Machine B (Apache JMeter Load Generator) must be separate physical/networked hosts. A co-hosted load generator steals CPU from the service and invalidates all latency measurements.

🔄 Gate 3: Open-Loop Load Generation Only

Traffic must be generated open-loop at controlled arrival rates via JMeter's Open Model Thread Group or Precise Throughput Timer. Closed-loop tests self-throttle and hide queue buildup; results from closed-loop tests are rejected.

📊 Gate 4: 100% Reconciled Log Audit Trail

Every p50, p95, and p99 latency figure on Slide 9 must directly reconcile with the raw JMeter .jtl files and internal Docker service logs. Fabricated or untraceable numbers trigger an academic integrity inquiry.

Subtask 1.1: Web Service API (FastAPI)

  • POST /tickets: Classifies single narrative via Ollama, stores to DB, returns category.

Member 2 · Alvin

Workload Analyst & Annotator B

Slides 3 & 4 • Domain & QA

Subtask 2.1: CFPB Workload Modeling

Analyze public CFPB dataset:

  • Estimate daily/hourly complaint volume and search queries.
  • Calculate peak vs non-peak arrival multipliers (done: peak ×3.4 over mean, ×16 over off-peak).
  • Compute narrative length character/token distributions (p50, p90, max).

Subtask 2.2: Independent Annotation (Annotator B)

Ensure ground truth rigour:

  • Receive 150–200 ticket sample from team's assigned 1,000 rows.
  • Independently label all tickets using Member 3's protocol.
  • Do NOT confer with Member 3 until both sets are completed.

Subtask 2.3: Quantitative SLA Formulation

Define testable requirements with specific load conditions:

  • Latency SLA (R1): POST /tickets p95 ≤ 15 s and p99 ≤ 30 s at the peak of 0.0167 tickets/s (1/min) with searches at 3×; R2: search p95 ≤ 1 s under the same load.
  • Throughput SLA (R3): at least 120 tickets/hour sustained (2× peak), achieved ≥ 95 % of offered, no queue build-up.
  • Accuracy SLA (R4/R5): at least 85 % overall on the golden set and at least 70 % recall in every category. R6: errors < 1 %, unparsed < 2 %.
